The Game Object

The Game Object

  • Inheriting behaviour breaks at scale
    • Objects can walk/run
    • Objects can fly
    • Objects maybe NPCs
    • Objects temporarily gain power-ups
  • Behaviour and data tightly coupled in classes
  • Memory poorly layed in
    • Non-contiguous storage means cache-misses

Composition over Inheritance

  • Game Devs began experimenting with composition in the early 2000s
    • Evolve Your Hierarchy - Mick West
    • Game Object Structure - Kyle Wilson
    • These focussed on the architectural benefits of composition
  • Brought to the mainstream at CppCon 2014 Data Oriented Design - Mike Acton (YouTube)

Data Oriented Design

  • Mike Acton reframed the discussion
    • Know you data
    • Understand your data
    • Design your data
  • Performance sky-rockets
  • Better cache usage
  • Contiguous storage

ECS: Fundamentals

  • Entity
    • Typically and integer handle
    • Cheap to copy around
  • Components
    • Ideally a struct with required data
    • Also cheap to copy around
  • Systems
    • A function that operates on components
    • Easy to reason about

EnTT

  • Free, Open Source ECS library (MIT)
  • Fastest on the market
  • Simple, clean API
  • Used in many games
    • Minecraft
    • Diablo II: Resurrected
    • Call of Duty: Vanguard

EnTT

  • Everything start with the Registry
    • Stores all entity IDs
    • Adds/removes components to entities
    • Provides views/groups to iterate entities

Wrapping Up

  • Libraries like SDL and EnTT make game programming simpler
  • ECS is versatile architectural model
    • Trivial to add behaviours to game objects
    • Cache-friendly nature yields better performance
  • Our Flappy Bird is playable
  • Some features can be added quickly
    • Use Triggers to create collectible power-ups
    • Combine with timers for invincibility
    • Use circle <-> AABB for collision detection
    • What else can you think of?
